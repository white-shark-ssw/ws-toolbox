# ws 工具箱

独立小工具集合。每个一级项目目录包含自己的源码、资源、使用说明和依赖，可独立运行与维护，不共用运行配置或 Python 虚拟环境。

当前仓库仍名为 `996Packtools`，计划由仓库所有者改名为 `ws-toolbox`；本次仅整理目录，不操作仓库名称。

## 项目

| 目录 | 工具 | 说明 |
| --- | --- | --- |
| [996-pack-tool/](996-pack-tool/) | 996 版本打包工具 | 服务端版本打包；升级分支另含独立客户端 Lua 加密/混淆。详见[项目说明](996-pack-tool/README.md)。 |

后续工具各自新增一个一级目录，项目的说明、依赖、测试、启动脚本和资源都放在对应项目内。暂不引入公共工具框架、统一依赖或总启动器。

## 当前分支

| 分支 | 打包工具版本 |
| --- | --- |
| `main` | v114 原始基线 |
| `upgrade/lua-protection` | v0.115 开发版：模块拆分、Lua 加密/混淆及客户端处理；实际引擎保护效果仍待验收 |

两条分支均采用 `996-pack-tool/` 目录。本次只迁移目录，不合并升级分支，不改变业务逻辑；此前版本仍可从 Git 历史找回。

## 使用方式

先进入 `996-pack-tool`，按该目录中的 README 操作。命令行安装依赖、启动和运行测试也应在项目目录中执行，不在仓库根目录执行。

升级分支 Windows 用户：进入 `996-pack-tool`，需要保护功能时先运行 `安装保护依赖.bat`，再运行 `启动工具.bat`。

### 旧用户本地配置

仓库不包含个人配置，Git 更新不会自动将未跟踪的本地配置搬进子目录。迁移前关闭工具并备份，再将以下原有内容复制到 `996-pack-tool/` 中，避免覆盖该目录中已经使用的新配置：

- `.group/`：打包组、规则及组内安全模板。
- `.manifest/`：文件变化基线。
- `.global_filter.json`：全局过滤设置。
- `.ui_config.json`：界面与开关设置。
- `.build_reports/`：如需保留原有构建摘要，可一并复制。

原始业务源码和导出目录不需要随仓库移动。配置中用户自设的绝对路径保持原值；自设相对路径或外部快捷方式需核对新项目位置。旧 Python 虚拟环境不要直接搬移，确有需要时在项目目录重新安装依赖。

## 目录整理校验

每条分支的新 `996-pack-tool/` 子树直接引用迁移前该分支的完整 Git 根树：全部原有文件的内容、文件模式及内部目录结构保持一致，包括原始 v114、图标、测试和项目说明。根目录保留工具集合说明及公共忽略规则；公共忽略规则也保护迁移后可能暂留在旧根目录的个人配置，避免误提交。

本次通过 Git 对象和路径映射核对目录迁移，不将历史自动测试结果当成本次重新执行的结果。
