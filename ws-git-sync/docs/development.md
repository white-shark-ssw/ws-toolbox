## 复现入口

在项目根执行：

```bash
uv run --frozen --extra dev ruff check .
uv run --frozen --extra dev ruff format --check .
uv lock --check --offline
uv run --frozen --extra dev pytest
uv run --frozen python -m ws_git_sync --smoke-test --smoke-report build/source-smoke.json
```

Linux无显示环境设置QT_QPA_PLATFORM=offscreen。启动检查使用隔离临时配置，不读取或覆盖用户配置，不执行生产Git同步。

测试使用临时bare remote、真实clone和独立工程夹具。WS_GIT_RESOLVER可指向可信官方解析器补充验证；不设置时使用测试接口夹具，产品运行时不存在夹具回退。框架解析器原文不进入工具源码。

## 已覆盖验证

- 新增、修改、删除、版本隔离、版本改名后的固定ID解析、重复同步与精确暂存。
- 服务端GBK/UTF-8与换行内容比较、XLS/客户端字节、过滤清单保存重载及大小写匹配。
- 源根缺失、读取拒绝、扫描变化、链接/重解析点、路径重叠、脏工作区和隐藏索引标记的停止条件。
- 外部修改、部分应用失败、提交hook改变内容和Push失败的现场保留；上传重试不重复提交。
- ahead/behind/diverged、快进、rebase冲突abort和原提交保全；不强推或自动解码合并冲突。
- 空目录、非空下载目录、损坏元数据、嵌套目录、初始化取消和后台恢复原操作。
- Qt主线程隔离、连续任务生命周期、未保存切换、布局恢复、日志追底、列表换行和八方向缩放。
- 配置使用真实EXE目录或源码项目根，不使用解包目录/cwd；旧配置只复制一次，损坏文件不覆盖。
- 公开默认地址与过滤项为空；已有配置保留地址和清单；未填写初始化地址仍可保存其他设置。
- autocrlf或attributes换行归一化不再误报暂存范围不一致；混合真实增改删正常提交，全为无差异项不空提交，真正漏暂存及计划外暂存仍失败并列出路径。
- GBK源、UTF-8仓库基线、LF/CRLF、autocrlf=false/true/input及text=auto交叉验证；空目录初始化后首次同步40个历史CRLF服务端文件，验证提交字节等于源且源字节/修改时间不变；篡改索引内容仍被拦截。

本轮环境为Linux x64、Python 3.12.14、PySide6 6.8.3：105项通过，1项Windows原生测试跳过；Ruff和锁文件校验通过。Windows原生测试跳过不视为通过。

## 下一步：Windows验收

1. 在Windows x64执行静态检查与完整pytest，记录Python、Qt和Git版本。
2. 双击build-onefile.bat，生成dist/wsGitSync.exe并确认冻结启动检查通过；目录式构建入口仍保留。
3. 将EXE放入独立可写目录，核对保存、重启、改变工作目录和迁入旧配置后，settings.json始终位于EXE旁。
4. 核对任务栏点击最小化/呼出、系统动画、三个窗口按钮、统一图标、窗口缩放和启动居中。
5. 验证100%/125%/150% DPI、跨屏、Excel/WPS及引擎占用下的文件读取。
6. 用可丢弃工程先预览、少量同步、再重复同步，核对真实源字节和修改时间未变化，再决定日常切换。

## 边界与公开发布

多文件应用不是整批原子事务，失败可能留下已应用项或未上传提交；不自动全仓reset。实例锁不能阻止其他Git客户端并发。上传完成不代表云端转码或表格派生完成。

源码不携带个人默认地址、业务默认过滤清单、个人配置、凭据、私有框架正文或私人交接资料。新配置使用前应自行核对过滤项；已有或迁入配置不清空。虚拟环境、构建缓存、临时测试仓库和发行中间物不提交。
