# ws Git 同步工具

Windows 桌面工具，按配置绑定真实 MirServer、真实 GUILayout 与仓库固定版本 ID。真实工程始终只读，文件只同步到 Git 副本。

当前版本：0.1.6 开发版。四个操作已实现并接入 Qt；Windows 打包与用户实机验收尚未完成，不能作为已验收发行版。

## 使用

1. 安装 Git，准备本地 ws 仓库，确认现有 Git 凭据可以正常拉取/上传。
2. 选择仓库根目录；“设置”调整目标分支（默认 main）、远端名称、可选 Git 程序路径和完整文件名过滤清单。
3. 新增配置，填写名称、真实 MirServer 根、真实 GUILayout 根、固定版本 ID（如 ver_001），保存。
4. 先预览范围，再同步。不要把客户端中间目录 dev 包进仓库，也不要把 UTF-8 镜像填成真实 GBK 服务端路径。

公开源码不预填个人仓库地址或业务文件名过滤清单。新配置首次使用前请在设置中核对过滤项；初始化时必须提供有效仓库地址。已有或自动迁入的 `settings.json` 中的地址、过滤清单及版本绑定保持原样，不因公开默认值为空而被重置。本机配置不要提交到公开仓库。

| 操作 | 行为 |
| --- | --- |
| 预览文件 | 本地 HEAD 为基线，不 pull、不复制、不提交、不上传 |
| 一键同步并上传 | 干净工作区 → ff-only 拉取 → ID 解析 → 扫描/核验 → 精确应用/暂存 → Commit → Push |
| 云端 → 本地 Git | 仅快进更新 Git 副本；不读取真实工程 |
| 本地 Git → 云端 | 仅处理已有提交；fetch 后 ahead 上传、behind 快进、分叉 rebase，冲突 abort |

分叉时不能保证无冲突。旧工具的 rebase 语义保留；编码冲突回归验证会中止并保全原提交，不会强推或擅自把真实工程覆盖到冲突文件。上传失败保留本地提交，可处理原因后使用上传已有提交入口重试。

## 界面与配置

默认外框 1080×720 逻辑像素，左栏 180、配置区 175，四个操作单行四色。保存后字段低强调，点击仍可编辑。版本列表独立滚动；差异和任务共用一个大日志区，支持复制、清空、暂停追底。窗口四边和四角可拖动缩放，尺寸随配置保存，每次启动在主屏可用区域居中；版本名称自动换行，列表项随内容撑高。背景使用略暗的白色调，窗口外框与分区有明确边线。分隔条可拖动，标题栏已移除“调整布局”；分隔条尺寸和窗口大小仍随配置保存。

配置统一放在程序旁：EXE版为`wsGitSync.exe`同目录的`settings.json`，源码版为`start.bat`/`pyproject.toml`同目录的`settings.json`。临时`instance.lock`也位于同目录，正常关闭后移除。首次运行仅在新位置没有配置时复制旧用户目录配置，旧文件保留；之后只使用同目录配置，不自动回退。目录不可写时明确报错。携带配置时将程序与settings.json一起移动。配置损坏或版本不兼容时停止并保留原文件。删除配置不删除工程。任务运行中锁定编辑/切换；关闭不会强制结束正在进行的任务。

## 源码运行与开发

使用 uv 管理项目环境和 Python 3.12。Windows 可直接双击 `start.bat`；脚本调用 uv，不依赖系统 Python Launcher。缺少所需 Python 时，uv 默认会下载运行时，首次运行需要联网；错误窗口会保留。当前尚无已验收 Windows EXE。

```bash
# 在含 pyproject.toml 的 ws-git-sync 目录内：
uv run --frozen --python 3.12 python -m ws_git_sync

# 开发检查：
uv run --frozen --extra dev ruff check .
uv run --frozen --extra dev ruff format --check .
uv run --frozen --extra dev pytest
```

Linux 无显示环境可设 `QT_QPA_PLATFORM=offscreen` 运行界面测试。`WS_GIT_RESOLVER` 可指向用户可信仓库的官方 `ws_versions.py`，回归时把该文件仅复制到临时 Git 夹具；未设置时使用测试用接口夹具。产品本身没有第二套解析器或后备规则。

架构与扩展规范见 [docs/architecture.md](docs/architecture.md)，实际进度与验证见 [docs/development.md](docs/development.md)。各模块职责已分开；核心测试不需要启动 Qt。

## Windows 构建

需要单个EXE时，在项目根目录双击 `build-onefile.bat`。脚本通过uv安装锁定构建依赖，使用PyInstaller onefile模式，内置Python、Qt与应用图标；完成后启动隔离冒烟检查，产物为 `dist/wsGitSync.exe`。发布时只分发该EXE，运行电脑仍须安装Git。脚本放在pyproject.toml所在目录，可直接用于当前源码包；单文件模式启动时会解压运行依赖。

在 Windows x64 使用 uv 安装项目锁定依赖、执行自动检查后：

```bash
uv run --frozen --extra dev python packaging/build_windows.py
```

产物是 `dist/wsGitSync/` 目录及 `dist/wsGitSync-windows-x64.zip`，目录内 EXE 与 `_internal` 必须一起分发。脚本会启动冻结 EXE 校验尺寸；这只证明该机器可启动，不能替代 Windows 10、125%/150% DPI、Excel/WPS 占用和真实工程验收。

依赖以 `uv.lock` 为准；`.python-version` 指定3.12系列。requirements两个锁定文件是为pip兼容导出的清单；依赖调整后从uv.lock重新导出，不单独维护第三套版本。

## 同步范围与限制

- 已收录文件：选中版本 MirServer 和 GUILayout 工程根内，先排除完整文件名过滤及派生文件。
- 新增服务端：Mir200/Envir/ws、Market_Def 递归 lua/txt/ini/cfg/json/csv；Data 顶层 xls。
- 新增客户端：GUILayout/ws、system、form 递归 lua/txt/json。
- 过滤精确匹配完整文件名、不区分大小写，同时跳过新增/更新/删除；清单由本机设置维护，公开源码默认为空。
- Data 派生 TSV/镜像状态由云端维护，本地跳过。GUILayout 顶层未收录文件不会自动补入。
- 服务端 GBK 与 HEAD UTF-8/暂态 GBK 按内容比较，换行仅在内存统一；写入保留真实源字节。XLS/客户端按字节处理。
- 链接、重解析点、源与仓库重叠、隐藏索引标记/稀疏检出均拒绝。读取失败不当作删除。
- 多文件应用不是整批原子事务。中途失败保留已应用项和现场，停止提交，不自动 hard reset。外部程序同时修改仓库时尽力复核并停止；本工具的单实例锁不能锁住其他 Git 客户端。
- 上传成功不等于云端 UTF-8/TSV 派生任务已完成；首版不观察 Actions。
- 仓库版本解析器是执行用户所选可信仓库中的 Python 代码，属于信任边界；不能将任意不可信仓库作为输入。


## 真源与同步顺序

真实工程始终是真源、只读。点击“一键同步并上传”：检查仓库干净和源路径独立 → 仅快进拉取到Git副本 → 根据版本ID解析目标 → 按真实工程构建增删改计划 → 写入Git副本对应工程目录 → 仅暂存本轮计划文件并提交 → 推送。拉取不回写真实工程；远端工程文件在纳入同步范围后仍以真实源为准，真实源中缺失的已收录文件会从Git副本删除。过滤项与Data派生文件跳过，新增仍受文件范围约束。

push上传的是分支尚未上传的提交，也包含本轮之前已创建的提交；不会自动提交计划外的未提交改动。GBK服务端按内容比较，需更新时保留原始字节写入Git副本；云端转码与TSV派生由Actions负责。

暂存时遵循仓库已有换行/属性处理。若计划中的修改经Git处理后与原提交相同，仅在Git副本文件仍等于稳定源快照、索引内容等于源的Git处理结果且等于原HEAD时跳过该项提交；其他真实变更继续正常提交。全为此类差异时不创建空提交，但仍上传已有提交。真正漏暂存或出现计划外文件时停止，并列出具体路径。


## Windows窗口与初始化

窗口按钮仅图标自绘，最小化/还原仍由Qt与Windows执行。程序设置独立AppUserModelID，并统一窗口、任务栏和EXE图标。Windows窗口保留系统菜单、缩放、最小化和最大化样式，通过原生消息只隐藏系统标题栏；任务栏切换与动画依赖实际Windows环境及系统动画设置。

输入非Git目录后，首次执行任一操作会提示是否初始化，并展示可修改的远端地址和当前分支。点击“初始化并连接”后才后台取得远端元数据：空目录检出仓库文件；非空目录只补.git，已有文件内容保留。若非空目录与远端有差异，后续任务会按干净工作区门禁停止，需先核对Git副本；不自动覆盖或提交原文件。损坏.git、嵌套仓库、真实工程重叠路径不初始化。取消后本次会话不重复提示同一路径，可重新启动后再次触发；远端地址也可在设置中修改。

设置中的过滤清单按完整文件名、不区分大小写生效；命中后新增、修改、删除全部跳过，原仓库已有副本继续保留。相似名称不匹配，过滤不改变真实工程。
