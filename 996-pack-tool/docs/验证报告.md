- 24 个交接作用域/注释案例，在 LF/CRLF、四组合和两个运行时中执行实际处理器；另有初始化右侧、递归、闭包、方法参数、循环、字段/全局/字符串与编码测试。

- 三种服务端入口 × 四组合；最终 ZIP Lua 内容摘要等于构建记录摘要。客户端文件/目录输入、大小写 Lua 扩展名、递归同结构输出、原文件不变。
- 单个坏文件不提交客户端新输出，ZIP 失败保留旧包；客户端提交中途故障恢复旧文件；取消、路径逃逸、源/目标重叠和硬边界拒绝。
- UTF-8、GBK 混合输入保留各自编码；关闭保护时，无 Lupa 环境也能普通打包。
- 完成处理使用任务启动时捕获的打包组，不会因为之后的界面状态变化把记录保存到另一组。

## 3. 实际业务与框架证据

等级突破使用交接包原始服务端 GBK、客户端 UTF-8 样例。每种组合、每个运行时均比较 582 个服务端场景、128 个客户端场景，共 5,680 组原版/处理版行为轨迹对照。ws、GUI、调度和引擎 API 是桩，不是实际引擎。

故意报错测试在处理后仍定位服务端第 144 行、客户端第 6 行；正常样例未插入这些故意错误。

`tests/fixtures/module_proxy.lua` 与 `module_registration.lua` 是固定快照中真实函数的摘录。在桩前提下执行原模块注册、main 代理、后续 main 赋值、渠道副本、data 访问、字符串回调，并模拟重建 ws / GameData 后重新加载。未宣称运行了整个 ws 框架。

固定快照为 `white-shark-ssw/ws-FrameWork@9b199b237504e67f339d3a8c7bc480d33bdd306a`。40 份输入按真实 Git blob SHA 核对（含不同编码/换行）；四组合共 160 次处理，两后端共 320 次编译检查全部通过。处理过程中核对非目标 token、局部绑定及换行不变量。名单与 SHA 见 `framework-audit.json`，可用 `scripts/verify_framework.py` 对同一快照复现。

## 4. 性能与包体

详细数据在 `performance.json`。以下为本容器独立测试，不代表用户引擎；加载只测解密与编译，跳过业务顶层初始化，3 次取中位数。

| 加密+混淆样例 | 原始字节 | 发布 Lua 字节 | Lua 5.1 加载 | LuaJIT 加载 |
| --- | ---: | ---: | ---: | ---: |
| 等级突破服务端 | 10,133 | 31,841 | 58.465 ms | 3.772 ms |
| 等级突破客户端 | 4,082 | 20,094 | 24.628 ms | 2.029 ms |
| SuperView 固定快照 | 167,690 | 290,555 | 815.282 ms | 40.879 ms |

发布 Lua 为未压缩字节数，不等同于最终 ZIP 增量。每个文件携带加载壳和十六进制密文，随机 key/nonce 和局部名会使后续产物略有不同。

已优化：有引擎内置 `bit` / `bit32` 时使用其位运算，否则使用纯 Lua 查表/算术后备；局部名称缩短但仍避开现有名称。没有新增游戏部署依赖。

合成函数每组执行 200,000 次、3 次取中位数：Lua 5.1 四组合约 6.10–6.52 ms，LuaJIT 四组合约 0.171 ms；业务调用阶段新增解密次数均为 0。只能证明这一合成调用不逐次解密，不能据此承诺所有真实业务零性能影响。

大文件、全框架冷启动和客户端反复加载仍是实测重点；纯 Lua 后备的加载开销明显，不能忽略。

## 5. 未验证和已知限制

- Windows 窗口实际排版、鼠标交互、启动 BAT 和冻结 EXE 尚未在 Windows 实机运行。窗口尺寸/位置已按约定接入，附有可在 Windows 自动运行的 Tk 检查。
- 未重新进行真实后台上传、整框架冷启动、全版本功能/跨服/战斗压力测试。交接包的早先引擎记录只适用于当时的参考样例，不替代本轮产物验收。
- 名称敏感反射采用保守拒绝策略；不能自动证明任意动态生成程序的名称依赖。局部名可能出现在日志中并发生变化；不支持任意 LuaJIT 扩展语法。
- 不支持 BOM、shebang、字节码或已知保护壳的再次保护；不静默降级。非标准格式应明确处理后再输入。
- 源文件扫描仍沿用 v114 的大小/整秒修改时间快捷判断；同大小、同时间戳的特殊修改可能漏检，本次没有重写该算法。
- 客户端回滚覆盖正常异常/取消，不保证断电或强制结束进程的全目录原子性；恢复失败时会保留恢复目录。
- 本轮没有实现产物缓存，没有构建 Windows EXE，也没有开发 HTML 界面校准工具。

## 6. 用户首次验收建议

1. 在独立测试目录运行完整新项目，保留现用工具。Windows 需要保护功能时，先运行 `安装保护依赖.bat`，再运行 `启动工具.bat`；普通打包不需要新增依赖。如需使用旧组，复制旧工具的个人配置和 `.group` 内安全模板到测试目录。
2. 先核对最小窗口下客户端行、两个颜色开关、原文件树交互；关闭保护，用一个熟悉的服务端包检查上传流程。
3. 再用等级突破等单功能验证仅混淆/仅加密/同时开启，确认前后端正常和日志行号，再扩展到框架冷启动、路由、通讯、列表和战斗场景。

本版是可测试开发产物，不应未经实际引擎验收直接替换线上整包。
