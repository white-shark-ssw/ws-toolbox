# v0.115 升级约定

以下约定以本次用户确认优先于交接包旧说明。

- 公共复选框“开启加密”（红色）、“开启混淆”（紫色）放在文件区域现有“打包完成后打开导出目录”右侧。
- 两项均关闭：原样处理；任一开启：先删除业务注释，保留换行与原始行号。混淆仅改词法绑定的局部名称；两项同时开启时业务混淆后加密，并混淆加载壳。必要的第三方许可保留。
- 仅 Lua 被保护处理。服务端其他文件沿用原有打包行为。
- 服务端母包、规则、勾选先确定最终清单，再处理暂存副本；源文件变化基线与发布内容摘要分离。
- 客户端是独立模块，与服务端共享保护处理器和公共开关，不套用服务端过滤、规则或基线。
- 客户端行在服务端导出目录下面、母包上面，仅含导入框、导出框、“加密/混淆”按钮，无浏览/打开按钮。
- 客户端导入可为 Lua 文件或目录。目录递归输出全部 Lua 的相对路径，不额外套导入目录名；单文件输出到指定文件夹并保留文件名。非 Lua 不输出。
- 客户端路径随打包组保存；原有组数据兼容。输出不得覆盖源文件。
- 最小窗口 1080×750，默认 1220×850；实际布局保留检查余量。
- 新任务启动时冻结本次选项和路径，后台处理期间防止串组、重复启动或修改任务参数。
- 输出失败不静默退回明文，不把半成品当成成功产物。已有可用 ZIP 必须保留到新包完成。
- HTML 控件校准工具不属于本轮优先范围。

引擎样例证据不等于全框架验收；自动检查、Windows UI 和真实引擎测试分开报告。
