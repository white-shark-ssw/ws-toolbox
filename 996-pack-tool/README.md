# ws 996 打包工具

996 服务端母包、规则包和勾选包工具，Python + Tkinter。

## 原始基线

`ws_pack_tool_v114.py` 是用户提供的 v0.114 原始源码，保持原字节，作为结构整理和功能回归的对照。运行：

```console
python ws_pack_tool_v114.py
```

Python 需要包含 Tkinter。运行配置保存在程序旁边；个人路径、打包组、安全模板及基线数据不进入仓库。

后续升级在独立开发分支实施，分开记录结构整理与 Lua 保护功能。

## 仓库位置与分支

本项目位于 `ws-toolbox/996-pack-tool/`。命令行安装依赖、启动和运行测试均应先进入本项目目录，不在仓库根目录执行。

| 分支 | 本项目版本 |
| --- | --- |
| `main` | v114 原始基线 |
| `upgrade/lua-protection` | v0.115 开发版：模块拆分、Lua 加密/混淆及客户端处理；实际引擎保护效果仍待验收 |

两条分支均采用本项目目录；目录整理未合并升级分支，也未改变业务逻辑。此前版本仍可从 Git 历史找回。

升级分支 Windows 用户：进入本项目目录，需要保护功能时先运行 `安装保护依赖.bat`，再运行 `启动工具.bat`。

## 从旧仓库根目录迁移配置

仓库不包含个人配置，Git 更新不会自动将未跟踪的本地配置搬进子目录。迁移前关闭工具并备份，再将以下原有内容复制到 `996-pack-tool/` 中，避免覆盖该目录中已经使用的新配置：

- `.group/`：打包组、规则及组内安全模板。
- `.manifest/`：文件变化基线。
- `.global_filter.json`：全局过滤设置。
- `.ui_config.json`：界面设置及升级版的开关设置。
- `.build_reports/`：如需保留升级版原有构建摘要，可一并复制。

原始业务源码和导出目录不需要随仓库移动。配置中用户自设的绝对路径保持原值；自设相对路径或外部快捷方式需核对新项目位置。旧 Python 虚拟环境不要直接搬移，确有需要时在本项目目录重新安装依赖。

## 目录整理记录

目录迁移时，每条分支的 `996-pack-tool/` 子树直接引用迁移前该分支的完整 Git 根树，核对全部原有文件的内容、文件模式及内部目录结构一致。原始 v114、图标及各分支已有的测试和项目说明均随项目迁移。仓库根目录的公共忽略规则也保护迁移后可能暂留在旧根目录的个人配置，避免误提交。

目录迁移通过 Git 对象和路径映射核对，未将历史自动测试结果当作迁移后重新执行的结果。本次 README 整理仅调整文档归属，不修改程序代码。

## 一键打包为单文件 EXE

在 Windows 中，将 `一键打包.bat` 放在本项目目录，双击运行即可。首次运行需联网；优先使用 uv，没有 uv 时使用已安装的 Python 3.10+（含 Tkinter）。脚本使用独立的 `build/.venv`，不修改日常运行环境。

脚本自动识别源码入口：本分支有 `ws_pack_tool.py` 时生成 `dist/ws_pack_tool.exe`，否则打包原版并生成 `dist/ws_pack_tool_v114.exe`。打包含图标；升级版还包含 Lupa 运行库、Lua 加密加载器及其许可文件，目标机器无需另装 Python/Lupa。

**配置在 EXE 旁边，按需创建，不写入单文件临时解压目录。** 包括 `.group/`、`.manifest/`、`.global_filter.json` 和 `.ui_config.json`；升级版的 `.build_reports/` 也位于 EXE 旁边。程序用 `sys.executable` 定位配置目录，内嵌图标和加载器则从打包资源位置读取。

打包不会嵌入、复制或覆盖个人配置。如果直接运行 `dist` 中的 EXE，要沿用旧组和基线，请先关闭程序，将旧配置及组内安全模板复制到 `dist`；也可以将 EXE 放进原有配置所在目录再启动。更换 EXE 时保留这些配置。程序所在目录需允许当前用户写入。

脚本只更新同名 EXE，不清空 `dist`；重新打包前关闭正在运行的旧 EXE。成功或失败都会保留控制台提示，便于查看结果。

本次对原版/升级版的冻结路径逻辑进行模拟，确认配置和资源路径分离、配置能在 EXE 旁持久化，并检查 BAT 的换行、跳转标签和打包参数。尚未在 Windows 中实际执行 BAT 或生成/运行 EXE，需首次构建后验证启动、配置保存重开及升级版的加密/混淆。
